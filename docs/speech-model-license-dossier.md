# Local Speech Model Licensing Dossier

**Status:** Stage 0 evidence, not release approval

**Reviewed:** 2026-09-01

**Scope:** local Hebrew and English STT/TTS artifacts suitable for a desktop VS Code extension with a 600 MB ceiling measured independently for each downloadable STT or TTS model pack. STT and TTS are separate packs and manifests; sizes in one pack are not added to, or used to excuse, the other.
**Evidence policy:** primary publisher repositories, model cards, project documentation, and licenses only. An engine license is never treated as a model-weight license. A dataset license is recorded separately and is not silently promoted to a weight license.

This is an engineering licensing screen, not legal advice. `PASS` means the public artifacts contain enough explicit permission for the stated technical use, subject to retaining notices and completing the separate quality/platform gates. `FAIL` means a documented restriction or hard product constraint rejects the candidate. `PENDING` means the public evidence is incomplete or requires legal, publisher, hardware, or human-review confirmation.

## Executive decision

- **STT licensing path:** OpenAI Whisper multilingual `base`, converted in-house from a pinned OpenAI checkpoint and run by a custom pinned, TTS-disabled sherpa-onnx helper, is the best current candidate. OpenAI explicitly applies MIT to code **and model weights**; Hebrew appears in the official tokenizer. A publisher-hosted sherpa conversion repository totals 453,071,794 bytes only because it contains mutually exclusive float/int8 graphs and test audio; a selected float encoder + float decoder + tokens triplet is 292,452,882 bytes, while the officially demonstrated matched int8 encoder + int8 decoder + tokens triplet is 160,609,290 bytes. These are orientation measurements, not the allowlist for the in-house conversion. The final STT pack must record the exact selected output bytes and hashes. Its **license gate passes**, but its Stage 0 quality/performance gate remains `PENDING` until the frozen Hebrew/English corpus and target hardware are measured.
- **English TTS licensing path:** Piper `en_US-ljspeech-medium` has a 63,531,379-byte ONNX file, a model card identifying a public-domain dataset, and is trained from scratch. It is acceptable as an English-only weight candidate, subject to notices and a compliant runtime. It does not satisfy the product requirement for local Hebrew TTS.
- **Hebrew TTS licensing path:** **No presently reviewed candidate is admissible for release.** The smallest lead with an explicit permissive weight label is [Matcha HE/EN](https://huggingface.co/thewh1teagle/matcha-tts): its 130,914,751-byte bilingual ONNX graph is labeled MIT and, with the 20,620,594-byte ReNikud ONNX front end, would select 151,535,345 bytes. It remains `PENDING` because the Matcha card does not identify the bilingual checkpoint's training dataset, base-checkpoint lineage, speaker authorization or voice-redistribution rights, and the ReNikud model card does not explicitly apply a license to `model.onnx`. Blue ONNX variants are the next technical leads, but their declared/associated dataset and speaker-rights chains are incomplete or potentially non-commercial. Piper Hebrew and several other public Hebrew models use SASPEECH, whose official license prohibits commercial use. Meta MMS Hebrew is CC-BY-NC-4.0. Therefore the overall local-voice gate remains `PENDING`, with **no Hebrew/bilingual TTS `PASS` candidate**, and product-source implementation must not be described as release-ready.

### Runtime conclusion

Use a TTS-disabled sherpa-onnx helper for the Whisper STT spike. For a BlueTTS-family TTS spike, ONNX Runtime Node or an independently packaged ONNX Runtime helper is the cleaner permissive runtime. Do not ship a current sherpa/Piper TTS binary under an Apache-only notice: upstream itself identifies the eSpeak GPL conflict.

## Why no Hebrew TTS candidate passes today

The blocker is not merely model quality. At least one of these documentary defects exists for every reviewed Hebrew option:

1. **Explicit non-commercial restriction:** SASPEECH-based Piper/F5/Kokoro/Mamre models and Meta MMS Hebrew cannot support unrestricted commercial redistribution.
2. **Incomplete provenance or artifact-level licensing:** Matcha HE/EN has an explicit MIT model-repository label, but omits its training corpus, base lineage and speaker/voice rights; ReNikud omits a model-card license for `model.onnx`. Blue v1/v2/v3 have MIT labels but incomplete checkpoint/data/style-rights chains, and BlueTTS 2.5 does not state a weight license at all. A source-code license is not enough.
3. **Unresolved copyleft boundary:** current sherpa/Piper TTS relies on GPL eSpeak/piper-phonemize. This may be distributable under a compliant GPL design, but it is not an Apache-only runtime and requires an explicit packaging/source/notice decision.
4. **No product acceptance evidence:** none of the candidates has evidence for this plan's Hebrew/English human intelligibility, code/path pronunciation, MOS, TTFB, stop latency, CPU/RSS and cross-platform thresholds.

Consequently, the Stage 0 local Hebrew TTS gate is **PENDING**, and the release remains blocked.

## Required manifest fields for any approved candidate

The eventual immutable model manifest must include, per artifact:

- model ID and pinned upstream revision;
- exact file path, byte size and SHA-256;
- engine/runtime version and compatibility range;
- weight license identifier and bundled license text;
- training dataset/provenance references;
- speaker/voice-style rights reference for TTS;
- required attribution/NOTICE text;
- commercial redistribution decision and reviewer/date;
- supported languages and whether support is measured or publisher-declared;
- frozen quality-report hash and supported platform matrix.

No candidate enters the download allowlist from this dossier alone.
